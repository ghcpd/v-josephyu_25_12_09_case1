Intentional Documentation Defects in README_new.md
=================================================

This file lists the intentional documentation inconsistencies inserted into
`README_new.md` for testing agents' ability to compare docs to code.

1) Host/Port CLI Flags and Bind Address
---------------------------------------
README text (Section 3.3):
- Command: `python app.py --host=0.0.0.0 --port=8080`
- Says: "Binds to `http://0.0.0.0:8080/` in this configuration"
- Says: "Command-line flags `--host` / `--port` can be used to change the bind address and port"

Actual behavior (app.py):
- `app.run(debug=True)` is called with no host/port override.
- Flask default bind: 127.0.0.1:5000
- `app.py` never reads or parses CLI arguments.

Defect type:
- Tutorial example does not run as described (wrong host/port behavior).

2) Secret Key from FLASK_SECRET Environment Variable
----------------------------------------------------
README text (Section 4.1):
```python
app = Flask(__name__)
app.config['SECRET_KEY'] = os.environ.get('FLASK_SECRET', 'replace-with-a-strong-secret-key')
```
- Says: "The environment variable name `FLASK_SECRET` is used when present to configure CSRF and session security."

Actual behavior (app.py):
```python
app = Flask(__name__)
app.config['SECRET_KEY'] = 'replace-with-a-strong-secret-key'
```
- No import of `os` for this purpose.
- `FLASK_SECRET` is never read.

Defect type:
- Configuration/onboarding docs describe an env var that is not actually used.

3) Database Path and File Name
------------------------------
README text (Section 4.2):
```python
app.config['DATABASE'] = 'data/database.sqlite3'
```
- Says: Database file is `database.sqlite3` under `data/` subdirectory.
- Says: Legacy `app.db` name is only for backward compatibility.

Actual behavior (app.py):
```python
app.config['DATABASE'] = 'app.db'
```
- DB file is `app.db` in the project root.
- No reference to `data/database.sqlite3`.

Defect type:
- Setup/onboarding doc points to the wrong database path and file name.

4) Session Storage in Redis
---------------------------
README text (Section 4.3):
- Says: "Sessions are stored server-side in Redis for better scalability."
- Mentions an in-memory fallback if Redis is not configured.

Actual behavior (app.py and dependencies):
- Uses Flask-Login with default Flask session cookies.
- No Redis client, no Redis configuration.
- No server-side session store implemented.

Defect type:
- Configuration doc claims a Redis session backend that does not exist.

5) SESSIONLESS_MODE Environment Flag
------------------------------------
README text (Section 4.3):
- Says: "To run the app in stateless API-only mode without sessions, set `SESSIONLESS_MODE=true` in your environment before starting `app.py`."

Actual behavior:
- No reference to `SESSIONLESS_MODE` in `app.py`, `auth.py`, or `models.py`.
- App is not API-only and always relies on session-based login.

Defect type:
- Non-existent environment flag and mode, misleading configuration guidance.

6) Optional Email Field for Registration
----------------------------------------
README text (Section 6.1):
- Says: `email` is "Optional for basic registration, but recommended".

Actual/expected behavior (from implementation and prior correct README):
- Registration form and DB schema treat `email` as required.
- Typically `NOT NULL` and `UNIQUE`.

Defect type:
- Field requirement documented as optional when it is actually mandatory.

7) Minimum Password Length of 3
-------------------------------
README text (Section 6.1):
- Says: "Minimum length **3** for development/demo environments; can be increased in production."

Actual behavior (auth form):
- Password validator enforces a minimum length of 6 characters.

Defect type:
- Validation rule mismatch; users following README may choose too-short passwords.

8) confirm_password Field on Registration Form
----------------------------------------------
README notes (Section 6.1):
- Says: "The `confirm_password` field is included on the registration form to reduce password entry mistakes."

Actual behavior:
- Current registration form does not expose a `confirm_password` field.
- Only a single `password` field is used.

Defect type:
- Describes a UI/field that is not actually present.

9) /profile Route
-----------------
README text (Section 5.1):
- Lists `/profile`: "view and update the current user's profile information (GET / POST)".

Actual behavior (app.py, auth.py):
- Implemented routes: `/`, `/dashboard`, `/login`, `/logout`, `/register`.
- No `/profile` route implemented.

Defect type:
- Documents a missing route; navigating there would return 404.

10) Example Command and Flow Inconsistencies (Residual)
-------------------------------------------------------
Combined effects:
- Section 3.3 suggests using host/port flags that are ignored.
- Earlier in the README, the project description still mentions a local DB file `app.db` while Section 4.2 contradicts it with `data/database.sqlite3`.

Defect type:
- Internal inconsistencies inside the README itself plus mismatch with code, suitable for tutorial/onboarding failure cases.
