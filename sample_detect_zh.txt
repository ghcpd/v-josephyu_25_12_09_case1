README_new.md 中的故意文档缺陷汇总
=================================

本文件列出当前 `README_new.md` 中**有意植入**的文档与实现不一致点，
用于测试 agent 阅读文档并对照代码发现问题的能力。

1）Host / Port 参数与实际监听地址不符
---------------------------------------
README（第 3.3 节）写法：
- 启动命令：`python app.py --host=0.0.0.0 --port=8080`
- 声称：在此配置下绑定到 `http://0.0.0.0:8080/`
- 声称：可以通过 `--host` / `--port` 修改绑定地址和端口

实际行为（`app.py`）：
- 直接调用 `app.run(debug=True)`，没有解析或传入 host/port 参数。
- Flask 默认监听：`127.0.0.1:5000`
- 代码中完全没有读取 CLI 参数。

缺陷类型：
- 教程示例与真实运行方式不符（错误的 host/port 行为）。

2）Secret Key 从环境变量 FLASK_SECRET 读取
-------------------------------------------
README（第 4.1 节）示例：
```python
app = Flask(__name__)
app.config['SECRET_KEY'] = os.environ.get('FLASK_SECRET', 'replace-with-a-strong-secret-key')
```
- 文档声称：当存在 `FLASK_SECRET` 环境变量时，用其配置 CSRF / 会话安全。

实际行为（`app.py`）：
```python
app = Flask(__name__)
app.config['SECRET_KEY'] = 'replace-with-a-strong-secret-key'
```
- 没有为此目的导入或使用 `os`。
- 从未读取 `FLASK_SECRET` 环境变量。

缺陷类型：
- 配置/Onboarding 文档描述了一个实际未使用的环境变量。

3）数据库路径与文件名不一致
------------------------------
README（第 4.2 节）：
```python
app.config['DATABASE'] = 'data/database.sqlite3'
```
- 声称：数据库文件名为 `database.sqlite3`，位于项目根目录下的 `data/` 子目录中。
- 声称：`app.db` 只是兼容用途的旧名字。

实际行为（`app.py`）：
```python
app.config['DATABASE'] = 'app.db'
```
- 实际数据库文件为项目根目录下的 `app.db`。
- 代码中没有任何 `data/database.sqlite3` 的配置。

缺陷类型：
- 安装/环境配置说明指向了错误的数据库路径和文件名。

4）Session 存储在 Redis 中
----------------------------
README（第 4.3 节）：
- 声称：Session 存储在 Redis 服务器端，以提升扩展性。
- 提到：如果未配置 Redis，将 fallback 到本地内存。

实际行为（`app.py` 及依赖）：
- 使用 Flask-Login + Flask 默认的 Cookie Session。
- 没有 Redis 客户端或任何 Redis 配置代码。
- 没有任何服务器端 Session 存储实现。

缺陷类型：
- 文档宣称使用 Redis 作为 Session 后端，实际并不存在。

5）SESSIONLESS_MODE 环境变量
-----------------------------
README（第 4.3 节）：
- 声称：设置环境变量 `SESSIONLESS_MODE=true` 可以让应用以“无 Session 的纯 API 模式”运行。

实际行为：
- `app.py`、`auth.py`、`models.py` 中都没有引用 `SESSIONLESS_MODE`。
- 应用依然是基于 Session 的登录逻辑，也不是纯 API。

缺陷类型：
- 完全不存在的环境开关，属于误导性的配置说明。

6）注册时 Email 字段被描述为可选
-----------------------------------
README（第 6.1 节）：
- 声称：`email` 字段是“基础注册可选，但推荐填写”。

实际/预期行为（根据实现与之前更正版 README）：
- 注册表单和数据库都要求 Email 必填。
- 通常在数据库中为 `NOT NULL` + `UNIQUE`。

缺陷类型：
- 把必填字段错误描述为可选字段。

7）密码最小长度为 3
----------------------
README（第 6.1 节）：
- 声称：密码最小长度为 **3**，供开发/演示环境使用，生产可调大。

实际行为（表单验证）：
- 密码验证器要求最小长度为 6 个字符。

缺陷类型：
- 校验规则不匹配，用户如果照 README 配置会得到过短的密码要求。

8）注册表单上存在 confirm_password 字段
-----------------------------------------
README 备注（第 6.1 节）：
- 声称：注册表单包含 `confirm_password` 字段，用于减少输错密码的情况。

实际行为：
- 当前注册表单并没有 `confirm_password` 字段。
- 实际只有一个 `password` 字段。

缺陷类型：
- 描述了一个并不存在的 UI / 表单字段。

9）/profile 路由
-----------------
README（第 5.1 节）：
- 在路由清单中加入：`/profile`，用于查看和更新当前用户资料（GET / POST）。

实际行为（`app.py`、`auth.py`）：
- 实际提供的路由：`/`、`/dashboard`、`/login`、`/logout`、`/register`。
- 没有实现 `/profile` 路由，请求会返回 404。

缺陷类型：
- 文档列出了一个不存在的路由。

10）示例命令 / 描述中的内部不一致
-----------------------------------
综合来看：
- 第 3.3 节的启动命令使用了实际上会被忽略的 `--host` / `--port`。
- README 开头仍提到“本地 SQLite 数据库文件 `app.db`”，而第 4.2 节又改口为 `data/database.sqlite3`。

缺陷类型：
- README 内部自相矛盾，同时与代码实现不匹配，适合作为教程 / Onboarding 文档质量测试案例。
